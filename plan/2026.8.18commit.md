# 2026.8.18 提交记录：OpenAI Provider Thinking 模式支持

## 改动文件

`src/providers/openai.ts`（+121 行，-6 行）

## 改动内容

### 改动前

`toolCall()` 方法对 `tool_choice` 参数硬编码为 `"required"`，即强制模型每次响应都必须调用工具。逻辑为单路径直发：

```
发送请求 → tool_choice="required" → 返回结果或抛出异常
```

这对大多数 OpenAI 兼容模型工作正常，但**与带推理模式（thinking/reasoning chain）的模型不兼容**——Qwen thinking 模型在 `tool_choice="required"` 时会直接返回 HTTP 400 错误：

> *The tool_choice parameter does not support being set to required or object in thinking mode*

### 改动后

引入 `LLMWIKI_TOOL_CHOICE_MODE` 环境变量，支持两种工具调用策略：

| 模式 | tool_choice | system prompt | 适用场景 |
|---|---|---|---|
| `strict`（默认） | `"required"` | 不修改 | 绝大多数模型，与改动前行为完全一致 |
| `thinking` | `"auto"` + 强指令追加 | 尾部追加 `[MANDATORY TOOL USE]` 段落 | Qwen thinking 等推理模型 |

调用流程变为：

```
读取 LLMWIKI_TOOL_CHOICE_MODE
  ├─ strict → tool_choice="required"（原逻辑）
  └─ thinking → tool_choice="auto" + 增强 prompt
                  ├─ 请求成功 → 返回结果
                  └─ 400 冲突 → 自动以 auto 重试
```

### 新增函数

| 函数 | 职责 |
|---|---|
| `getToolChoiceMode()` | 读取环境变量，返回 `"strict"` 或 `"thinking"` |
| `isThinkingModeEnabled()` | 布尔判断快捷函数 |
| `enhanceSystemPromptForThinkingMode(system)` | 在 system prompt 尾部追加强制工具调用指令 |
| `isToolChoiceConflictError(error)` | 判断异常是否为 tool_choice 与 thinking 模式的 400 冲突 |
| `retryToolCallWithAutoChoice(...)` | 冲突时的自动降级重试（`tool_choice="auto"`） |

## 改动意义

1. **兼容 Qwen thinking 等推理模型**——改动前使用这类模型会直接报 400 崩溃，改动后可正常工作。
2. **零破坏性**——默认模式 `strict` 与原行为完全一致，不设环境变量的现有用户无感知。
3. **双保险容错**——thinking 模式同时使用"增强 prompt"主动防御和"400 错误自动重试"被动防御，健壮性更高。
4. **扩展性**——`getToolChoiceMode()` 返回联合类型，未来新增策略只需扩展联合类型和分支即可。

## 配置与使用方法

### 1. 使用 DashScope Qwen thinking 模型

```bash
# .env 或 export
LLMWIKI_PROVIDER=openai
OPENAI_API_KEY=sk-your-dashscope-key
OPENAI_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLMWIKI_MODEL=qwen-max                    # 或其他 thinking 模型
LLMWIKI_TOOL_CHOICE_MODE=thinking          # ← 关键配置
```

### 2. 使用标准 OpenAI 模型（无需改动）

```bash
LLMWIKI_PROVIDER=openai
OPENAI_API_KEY=sk-xxx
LLMWIKI_MODEL=gpt-4o
# 不需要设置 LLMWIKI_TOOL_CHOICE_MODE，默认 strict
```

### 3. 使用兼容 OpenAI 协议的本地模型

```bash
LLMWIKI_PROVIDER=openai
OPENAI_API_KEY=any-placeholder             # 本地服务通常忽略 key
OPENAI_BASE_URL=http://localhost:8000/v1
LLMWIKI_MODEL=your-local-model
# 如果模型支持 thinking，设置 LLMWIKI_TOOL_CHOICE_MODE=thinking
```

### 4. 环境变量完整参考

| 变量 | 必需 | 默认值 | 说明 |
|---|---|---|---|
| `LLMWIKI_PROVIDER` | 是（用 OpenAI 时） | `anthropic` | 设为 `openai` |
| `OPENAI_API_KEY` | 是 | — | API 密钥 |
| `LLMWIKI_MODEL` | 否 | `gpt-4o` | 补全模型 ID |
| `LLMWIKI_EMBEDDING_MODEL` | 否 | `text-embedding-3-small` | 嵌入模型 ID |
| `OPENAI_BASE_URL` | 否 | OpenAI 官方 API | 自定义端点 |
| `OPENAI_EMBEDDINGS_BASE_URL` | 否 | 同 `OPENAI_BASE_URL` | 嵌入 API 单独指向不同端点 |
| `LLMWIKI_TOOL_CHOICE_MODE` | 否 | `strict` | `strict` 或 `thinking` |
| `LLMWIKI_REQUEST_TIMEOUT_MS` | 否 | `600000`（10分钟） | 单次请求超时（毫秒） |
