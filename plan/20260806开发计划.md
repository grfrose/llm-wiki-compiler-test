### 改动 1：修改概念提取 Prompt（`src/compiler/prompts.ts:buildExtractionPrompt`）

**文件**: `src/compiler/prompts.ts`  
**函数**: `buildExtractionPrompt` (第 119-148 行)  
**改动位置**: 第 130-134 行

#### 当前代码
```typescript
// 第 129-134 行
return [
  ...withLangLine(
    "You are a knowledge extraction engine. Analyze the following source document",
    "and identify 3-8 distinct, meaningful concepts worth documenting as wiki pages.",
    "Each concept should be a standalone topic that someone might look up.",
    "Focus on key ideas, techniques, patterns, or entities — not trivial details.",
    "Use the extract_concepts tool to return your findings.",
  ),
```

#### 改动后代码
```typescript
return [
  ...withLangLine(
    "You are a knowledge extraction engine. Analyze the following source document",
    "and identify all distinct, meaningful concepts worth documenting as wiki pages.",
    "Each concept should be a standalone topic that someone might look up.",
    "Focus on key ideas, techniques, patterns, or entities, including supporting details,",
    "data points, examples, and illustrative cases from the source material.",
    "Use the extract_concepts tool to return your findings.",
  ),
```

#### 改动理由

| 问题代码 | 问题原因 | 改动目的 |
|---------|---------|---------|
| `"identify 3-8 distinct, meaningful concepts"` | **硬限制概念数量**。一篇包含 20 个重要概念的论文只能提取 3-8 个，其余丢失。 | 移除数量限制，改为 `"identify all distinct, meaningful concepts"`，让 LLM 自主判断数量。 |
| `"Focus on key ideas... — not trivial details."` | LLM 被指令主动过滤"琐碎细节"，但"琐碎"的定义由 LLM 自主判断，导致用户认为重要的细节（数据点、示例、代码片段）被丢弃。 | 改为积极指令：`"including supporting details, data points, examples..."`，明确鼓励保留细节。 |

**参考**: llm_wiki 的 prompt 无数量限制，且明确要求 "Include ALL relevant information"。

#### 4.1 Schema 文件设计

**文件**: `.llmwiki/schema.md`  
**职责**: 定义页面类型 → 目录路由规则 + frontmatter 规范

**示例内容**:
```markdown
# Wiki Schema

## Page Types

### entity
- directory: `entities/`
- description: "Concrete entities: people, organizations, tools, technologies."
- frontmatter:
  - kind: entity
  - title: string
  - tags: list[string]
  - aliases: list[string] (optional)
  - sources: list[string]
  - related: list[string]
  - status: string ("stub" | "mature" | "deprecated")
  - date: date
  - aliases: list[string]

### concept
- directory: `concepts/`
- description: "Abstract ideas, principles, patterns, methodologies."
- frontmatter:
  - kind: concept
  - title: string
  - tags: list[string]
  - sources: list[string]
  - related: list[string]
  - status: string
  - date: date

### source
- directory: `sources/`
- description: "Raw source material summaries and references."
- frontmatter:
  - kind: source
  - title: string
  - original_filename: string
  - sources: list[string]

## Validation Rules
- Page path must match type directory (e.g., `entities/foo.md` → type: entity)
- Frontmatter must include required fields for the page type
- `related` field should contain `[[wikilinks]]`
```

**解析逻辑** (新增 `src/utils/schema.ts`):

  description: string;
  frontmatter: Record<string, string | undefined>;
}

export interface WikiSchema {
  pageTypes: Record<string, PageType>;
  validationRules?: string[];
}

/** Parse schema.md file into WikiSchema object. */
export function parseSchema(markdownContent: string): WikiSchema {
  // 实现 Markdown → WikiSchema 解析
  // 参考 llm_wiki/src/lib/wiki-schema.ts 的 parseWikiSchemaRouting()
}

/** Get page type name from file path. */
export function getPageType(filePath: string, schema: WikiSchema): string | undefined {
  const dir = path.dirname(filePath);
  return Object.entries(schema.pageTypes)
    .find(([_, type]) => type.directory === `${dir}/`)
    ?.[0];
}

#### 4.2 Purpose 文件设计

**文件**: `.llmwiki/purpose.md`  
**职责**: 定义 Wiki 知识库的目标、受众、关键问题，注入到 prompt 中指导 AI。

**示例内容**:
```markdown
# Wiki Purpose

## Goal
Build a comprehensive knowledge base for distributed systems architecture,
covering CAP theorem, consensus algorithms, and real-world case studies.

## Audience
- Senior backend engineers designing distributed systems
- Tech leads evaluating consensus algorithms
- DevOps engineers implementing fault-tolerant infrastructure

## Key Questions
1. What are the trade-offs between strong vs eventual consistency?
2. How do different consensus algorithms (Raft, Paxos, Zab) compare in practice?
3. What are the failure modes of popular distributed databases?

## Principles
- Prioritize practical implementation details over theoretical proofs
- Include real-world failure cases and mitigations
- Document quantitative metrics (latency, throughput, recovery time)
```

**解析逻辑** (新增 `src/utils/purpose.ts`):
```typescript
export interface WikiPurpose {
  goal?: string;
  audience?: string[];
  keyQuestions?: string[];
  principles?: string[];
}

/** Parse purpose.md file into WikiPurpose object. */
export function parsePurpose(markdownContent: string): WikiPurpose {
  // 实现 Markdown → WikiPurpose 解析
  // 提取 ## Goal, ## Audience, ## Key Questions, ## Principles 等章节
}

/** Format purpose into prompt context string. */
export function formatPurposeForPrompt(purpose: WikiPurpose): string {
  const parts: string[] = [];
  if (purpose.goal) parts.push(`Goal: ${purpose.goal}`);
  if (purpose.audience) parts.push(`Audience: ${purpose.audience.join(", ")}`);
  if (purpose.keyQuestions) parts.push(`Key Questions:\n${purpose.keyQuestions.map(q => `- ${q}`).join("\n")}`);
  if (purpose.principles) parts.push(`Principles:\n${purpose.principles.map(p => `- ${p}`).join("\n")}`);
  return parts.join("\n\n");
}
```
