## 一、产品定位差异

| 维度 | **llm_wiki** (生态) | **llm-wiki-compiler-test** (CLI 工具) |
|---|---|---|
| **本质** | 知识工作**平台生态**，含 Web 应用 + Agent + 技能 | 知识**编译器**，独立 CLI 工具 |
| **隐喻** | 工作区 + 编辑器 + 代理助手 | 编译器（像 gcc 一样把原料编译成成品） |

| **AI 角色** | AI 直接写 wiki（实时协作编辑） | AI 编译管道操作者（批量处理后生成） |

## 二、构建架构的根本差异

### llm_wiki：三阶段精细化流水线

```
源文件 → [Stage 0: 预处理] → [Stage 1: 深度分析] → [Stage 2: 页面生成] → wiki/
```

**核心代码**：`src/lib/ingest.ts`（3441 行核心函数 `autoIngest()`）

| 阶段 | 做什么 | 关键函数 |
|---|---|---|
| Stage 0.5 | 图像提取（PDF/PPTX/DOCX 中的嵌入图） | `extractAndSaveSourceImages()` |
| Stage 0.6 | 图像标注（Vision LLM 生成描述） | `captionMarkdownImages()` |
| Stage 1 | **深度分析**：提取实体、概念、论点、连接、矛盾 | `buildAnalysisPrompt()` → LLM |
| Stage 2 | **页面生成**：基于分析结果生成多个 wiki 页面 | `buildGenerationPrompt()` → LLM |
| Stage 3 | 写入文件 + 更新索引 + 生成嵌入 | `writeFileBlocks()` → `embedPage()` |

**关键洞察**：分析阶段和生成阶段**分离**，LLM 先完整理解文档，再据此生成多个页面。

## 三、Prompt 设计差异（细节丢失的根源）

### llm_wiki 的 Stage 1 分析 Prompt

**文件**: `llm_wiki/src/lib/ingest.ts` (行 2081-2137)

```
You are an expert research analyst. Read the source document and produce a structured analysis.

## Key Entities     ← 要求列出所有人、组织、产品、数据集、工具
## Key Concepts     ← 理论、方法、技术
## Main Arguments & Findings  ← 核心主张、证据强度
## Connections to Existing Wiki  ← 与现有页面的关联
```

### llm-wiki-compiler-test 的 Phase 1 提取 Prompt

**文件**: `src/compiler/prompts.ts` (行 119-148)

```
You are a knowledge extraction engine. Analyze the following source document
and identify 3-8 distinct, meaningful concepts worth documenting as wiki pages.
Each concept should be a standalone topic that someone might look up.
Focus on key ideas, techniques, patterns, or entities — not trivial details.  ⚠️
Use the extract_concepts tool to return your findings.

For every concept, emit provenance metadata so downstream tools can reason
about reliability:
  - confidence: 0..1 — how certain you are the source supports this concept.
  - provenance_state: 'extracted' if directly stated, 'merged' if synthesised
    from multiple parts of the source, 'inferred' if reasoned from context,
    or 'ambiguous' if the source is contradictory or unclear.
  - contradicted_by: slugs of other concepts (in this batch or the index)
    whose evidence conflicts with this one.

[Existing wiki index for deduplication]

[sourceContent]
```

**问题所在**：
1. `"3-8 distinct concepts"` → **硬性数量限制**，复杂文档的细节被丢弃
2. `"not trivial details"` → **明确指示忽略细节**
3. `"standalone topic"` → 要求独立性，丢失上下文关联
4. 输出 schema 要求 `summary: "One-line description"` → **强制一行摘要**

### llm_wiki 的 Stage 2 生成 Prompt

**文件**: `llm_wiki/src/lib/ingest.ts` (行 2142-2309)

```
You are a wiki maintainer. Based on the analysis, generate wiki files.

## IMPORTANT: Source File - All pages MUST include filename in frontmatter sources field
## Project Schema and Routing (AUTHORITATIVE) - Use schema-defined folders
## Frontmatter Rules (CRITICAL) - Strict YAML format

## Output Format (MUST FOLLOW EXACTLY)
---FILE: wiki/entities/openai.md---
---
type: entity
title: OpenAI
created: 2026-08-05
tags: [ai, research]
```

**关键约束**：
- 第一行必须是 `---`
- related 字段使用 bare slugs（不是 `[[wiki/page]]`）
- sources 字段追踪知识来源
- 解析器处理 CRLF 行尾、代码 fence 内的标记、流截断的 unclosed blocks
- 路径安全检查（防止 `../../../etc/passwd`）

### llm-wiki-compiler-test 的 Phase 2 生成 Prompt

**文件**: `src/compiler/prompts.ts` (行 159-204)

```
You are a wiki author. Write a clear, well-structured markdown page about "{concept}".
Draw facts only from the provided source material.
Include a ## Sources section at the end listing the source document.
Suggest [[wikilinks]] to related concepts where appropriate.
Write in a neutral, informative tone. Be concise but thorough.  ⚠️

Source attribution: at the end of each prose paragraph, append a citation
marker identifying which source file(s) and line range the paragraph drew from.
PREFERRED format: ^[filename.md:START-END] where START and END are the line numbers
shown in the numbered source content below (e.g. ' 42 | some text' → line 42).
Use this whenever you can identify the specific numbered lines supporting the claim.
Fallback format: ^[filename.md] when the claim draws from the source broadly and
no specific line range applies. For multi-source paragraphs: ^[a.md:1-5, b.md:10-12].
Place citations only at the end of prose paragraphs or sentences — not on
headings, list items, or code blocks.
Do not cite YAML frontmatter lines (the --- ... --- block at the top of a file) as
source evidence for substantive claims — those lines are metadata, not content.
If a claim relates to a metadata field (e.g. document date or author), leave it uncited.
Source filenames are visible as `--- SOURCE: filename.md ---` headers in the content below.

If a paragraph is your inference rather than a direct extraction, leave it
uncited — downstream lint rules will count uncited paragraphs as 'inferred'
so lint can surface excess-inferred-paragraphs warnings on review.

[Existing page to update]
[Related wiki pages for cross-referencing]

--- SOURCE MATERIAL ---

[numbered sourceContent with line numbers]
```

**问题所在**：
1. `"Be concise but thorough"` → **"concise" 倾向被 LLM 优先执行**
2. 没有明确要求"preserve all details"或"complete coverage"
3. 推断段落可以 uncited → 允许 LLM 自行推断内容

## 四、Schema/purpose.md 的作用

### llm_wiki 的 Schema 驱动路由

`src/lib/templates.ts` 定义了 5 种项目模板，每种模板的 `schema.md` 包含：

```
| Type       | Folder              | Description                                            |
|------------|---------------------|--------------------------------------------------------|
| entity     | wiki/entities/      | Named things (people, tools, organizations)            |
| concept    | wiki/concepts/      | Ideas, techniques, phenomena, frameworks               |
| source     | wiki/sources/       | Papers, articles, talks, books                         |
| comparison | wiki/comparisons/   | Side-by-side analysis of related entities              |
| synthesis  | wiki/synthesis/     | Cross-cutting summaries                                |
| overview   | wiki/               | High-level project summary                             |
```

**扩展模板**：
- **Research 模板**: 额外添加 thesis/, methodology/, findings/ 目录
- **Reading 模板**: 额外添加 characters/, themes/, plot-threads/, chapters/ 目录
- **Personal Growth 模板**: 额外添加 goals/, habits/, reflections/, journal/ 目录
- **Business 模板**: 额外添加 meetings/, decisions/, projects/, stakeholders/ 目录

#### purpose.md（知识库的"灵魂"）

**文件示例**: `/PROJ2/FLOAT/gaoruifeng/llm_wiki/purpose.md`

定义知识库的**目标和边界**：
- **Goal**：构建知识库的目标（如"构建寻因生物单细胞组学技术支持知识库"）
- **受众**：内部同事/外部客户
- **回答原则**：必须基于原始文档、严禁编造、版本敏感信息标注等
- **数据脱敏规则**：合同编号、批次号、姓名、样品号等隐私处理
- **关键问题**：驱动知识库建设的核心问题列表
- **知识域范围**：In scope / Out of scope 明确边界
- **使用场景**：售后技术支持、新人培训、售前决策支持、AI Agent 辅助等

#### Schema 解析与验证

**文件**: `llm_wiki/src/lib/wiki-schema.ts`

```typescript
// 第 8-26 行 - 加载 schema
export async function loadProjectWikiSchemaRouting(
  projectPath: string,
): Promise<WikiSchemaRouting | null> {
  let raw = "";
  try {
    raw = await readFile(`${projectPath.replace(/\/+$/, "")}/schema.md`);  // ← 读取 schema.md
  } catch {
    return null;
  }
  
  const routing = parseWikiSchemaRouting(raw);
  return Object.keys(routing.typeDirs).length > 0 ? routing : null;
}

// 第 27-45 行 - 解析 Page Types 表格
export function parseWikiSchemaRouting(markdown: string): WikiSchemaRouting {
  const typeDirs: Record<string, string> = {};
  for (const line of pageTypesSectionLines(markdown)) {
    if (!line.trim().startsWith("|")) continue;
    const cells = line.split("|").slice(1, -1).map((cell) => cell.trim());
    if (cells.length < 2) continue;
    
    const [type, dir] = cells;  // ← 提取 type 和 directory
    if (!/^[a-z][a-z0-9_-]*$/i.test(type)) continue;
    if (dir !== "wiki" && !dir.startsWith("wiki/")) continue;
    
    typeDirs[type] = stripTrailingSlash(dir);  // ← 建立映射：{ "entity": "wiki/entities", "concept": "wiki/concepts", ... }
  }
  return { typeDirs };
}

// 第 66-89 行 - 验证页面路由
export function validateWikiPageRouting(
  relativePath: string,
  content: string,
  routing: WikiSchemaRouting,
): WikiSchemaRoutingIssue | null {
  const parsed = parseFrontmatter(content);
  const type = parsed.frontmatter?.type;
  
  const expectedDir = routing.typeDirs[type];  // ← 从 schema 获取期望目录
  const actualDir = dirname(normalizedPath);
  
  if (expectedDir && actualDir !== expectedDir) {
    return {
      message: `Page type "${type}" must be under "${expectedDir}/". Current directory: "${actualDir}".`,
    };
  }
  return null;
}
```

## 五、内容截断策略对比

### llm_wiki：智能分块

**文件**: `llm_wiki/src/lib/text-chunker.ts`

```typescript
chunkMarkdown(content, {
  targetChars: 1000,
  maxChars: 1500,
  overlapChars: 200,
  minChars: 200
})
```

**分块优先级**（按 Markdown 语义）：
1. Heading 边界（`##` / `###` / `####`）
2. 段落边界（`\n\n`）
3. 行边界（`\n`）
4. 句子终止符（`. ` / `。` / `!` / `？`）
5. 空白字符
6. 硬截断（最后手段）

**保护机制**：
- ❌ 不拆分 fenced code block（``` ... ```）
- ❌ 不拆分 Markdown table（| ... |）
- ❌ 移除 YAML frontmatter（不浪费 token）

**每个 chunk 保留 heading 路径 breadcrumb**（如 `## Intro > ### Usage`），查询时能精确定位上下文。

### llm-wiki-compiler-test：简单字符截断

**文件**: `src/compiler/prompt-budget.ts`

```typescript
const DEFAULT_PROMPT_BUDGET_CHARS = 200_000;  // 20 万字符预算

// 超出预算时：平均分配 + 硬截断
const perSource = Math.floor(budget / slices.length);
const trimmed = slices.map(s =>
  s.content.length > perSource
    ? s.content.slice(0, perSource) + "\n\n[…truncated for prompt budget — see #39…]"
    : s
);

function buildBudgetedCombinedContent(
  concept: string,
  slices: SourceSlice[],
): string {
  const budget = resolvePromptBudgetChars();  // 默认 200,000
  const totalRaw = slices.reduce((sum, s) => sum + s.content.length, 0);

  if (totalRaw <= budget) {
    return formatSlices(slices);
  }

  // ⚠️ 当超出预算时，平均分配给每个源文件
  const perSource = Math.max(1, Math.floor(budget / slices.length));
  warnTruncation(concept, totalRaw, slices.length, perSource, budget);

  // ⚠️ 简单截断，添加标记
  const trimmed = slices.map((s) =>
    s.content.length > perSource
      ? { ...s, content: s.content.slice(0, perSource) + TRUNCATION_MARKER }
      : s,
  );
  return formatSlices(trimmed);
}
```

**问题**：
